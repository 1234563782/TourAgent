## 实际变更

- 默认 CLI 使用 PostgreSQL，不再用 SQLite 保存新会话或长期记忆。
- 使用独立 `travel_memory` schema，复用已有政策数据库连接和公司标识。
- 偏好与行程绑定公司/用户；检查点绑定公司/用户/会话。
- Agent 构建检查记忆和检查点身份一致，防止上层错误绑定不同用户。
- 使用官方 `langgraph-checkpoint-postgres==3.1.2`，保留 SQLite 依赖用于迁移与离线测试。
- 增加显式初始化、只读清点、迁移预检、按用户事务导入与源摘要幂等记录。
- 迁移保留完整检查点、父关系、旧元数据、中间写入及正负索引，
  提交前回读逐项比较；发生冲突或核验失败则回滚本用户全部导入。
- 未修改真实 `.env` 中的任何配置，未修改政策记录，未调用模型或供应商服务。

## 怎样验收

完整回归使用项目 `.venv` 和 pip 工具链：

```powershell
$env:TRAVEL_TEST_POSTGRES = "1"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:TRAVEL_TEST_POSTGRES
.\.venv\Scripts\python.exe -m pip check
git diff --check
```

最终输出摘要：

```text
Ran 150 tests in 8.095s
OK

No broken requirements found.
```

真实 PostgreSQL 测试在随机 `travel_memory_test_*` schema 中运行，
写入合成偏好、行程、检查点，测试后清理本次测试 schema。
模型使用脚本化响应，因此下面的“提问”用于驱动真实 LangGraph 和数据库流程，
不是让真实大模型自主选择工具；“Saved”“Cancelled”等是明确预设的模型文本。
最终判断依赖数据库回读及断言，不以模型声称保存成功作为证据。

| 场景或测试输入 | 期望 | 实际结果 |
| --- | --- | --- |

| `Remember my seat`，工具提交靠过道偏好，断开连接后再确认 | 确认前不写偏好；重建后可以确认 | 通过，中断恢复后才写入 |
| `Remember`，确认选择拒绝 | 不保存偏好 | 通过，数据库偏好仍为空 |
| `Save`，提交合成草案，重启后确认 | 确认前无行程，确认后保存一次 | 通过，回读与草案一致 |
| `Private question`，随后换用户、换公司或换 session | 相同 session 名称也不能串会话 | 通过，跨用户访问被拒绝，新会话为空 |
| 同一旧源数据迁移两次，中间在 PostgreSQL 改偏好 | 第二次不覆盖新偏好 | 通过，返回 `already_imported` |
| 目标已有同 ID 不同行程，再迁入旧偏好和行程 | 整个用户导入回滚 | 通过，偏好未写入，原行程保留 |
| 目标已有同名会话，再导入旧检查点 | 不覆盖现有会话，业务数据一并回滚 | 通过，旧数据没有部分提交 |
| SQLite 中 `Remember` 触发待确认偏好，迁移后同意 | 保留待确认任务，写入新偏好 | 通过，重建图后恢复并保存靠窗偏好 |
| 同样的迁移后选择拒绝 | 保留原偏好，不写待确认新偏好 | 通过，靠过道偏好保持不变 |
| 初始化再次执行 | 不清空已有数据 | 通过，偏好保留 |
| 注入检查点回读核验失败，再重跑正常导入 | 失败事务无残留，正常重试可成功 | 通过，业务记录、检查点、导入标记均回滚 |
