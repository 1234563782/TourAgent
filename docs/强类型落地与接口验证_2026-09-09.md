# 强类型落地与接口验证

日期：2026-09-09。本文区分程序修复、真实模型实验与尚未完成的业务验收。

## 结论

1. 当前配置链路接受strict工具参数，但空枚举探针仍返回分类值，违反请求schema。
   因此不能把strict参数被接受当成服务端强约束保证。未切换模型或端点。
2. 已修复生产槽位更新的一类误拒绝：同事项、同版本校验后，完全相同且未提供新证据的
   字段按无变化处理，不要求重新引用，也不覆盖旧证据或增加历史记录。
   真实变化、撤回、显式提交的引用仍按原规则验证。
3. 强类型假设候选只增加scenario及scenario_evidence；程序隔离测试通过，
   但真实新题仍会把假设写入实际区，不能接入生产。
4. 全量299项测试，278通过、21项数据库测试跳过。不是企业差旅端到端验收通过。

## 接口能力探测

脚本：`scripts/probe_structured_output.py`。使用现有venv、配置和模型工厂；
不打印凭证、响应正文、服务地址或异常原文。不自动切换到其他端点。

| 探针 | 结果 | 可得结论 |
| --- | --- | --- |
| 最小strict工具schema | 响应通过本地校验 | 本次模型输出合法，不能单独证明强约束 |
| required为空的strict对象 | 仍返回合法分类 | 此schema在一般JSON Schema中允许，不能单独作为忽略约束的证据 |
| 原生response_format=json_schema | HTTP 400 | 本次配置和请求失败，未定位供应商具体限制 |
| 必填category的enum为空 | 仍返回分类值 | 返回参数违反所传schema，本次链路未强制执行约束 |

`schema_valid`字段检查的是基准ProbeResult合同；
空枚举探针另外记录`requested_schema_satisfied=false`，不可混为一谈。
拒绝、超时等边界没有全部做真实故障注入；鉴权/连接失败停止行为有离线测试。

证据：
- `.verification/structured-capability-20260909-v1.json`：沙箱连接失败，保留。
- `.verification/structured-capability-20260909-v2.json`：3次真实探测。
- `.verification/structured-capability-20260909-v3.json`：空枚举补充探测。

官方网页未取得strict协议正文，先前关于Beta和required的文档描述没有在本轮核实，
不作为报告依据。结论来自当前配置链路的实际响应，也不能外推到其他供应商或端点。

## 生产修复

文件：`business_travel/slots.py`。

模型在更正一笔费用时，有时把原日期、城市等原样重复提交，却没有本轮证据。
此前程序把每个提交字段都当成新事实，整笔更正被拒绝。

新行为：
- 先按原逻辑验证事项ID、版本、业务域以及证据键集合。
- 仅对update，过滤与现有值相同且未提交证据的字段。
- 真正变化的字段仍必须有本轮原文引用。
- 显式提供了旧引用或不合法引用，仍拒绝，不通过删除引用绕过检查。
- 新事项不适用过滤；已有字段未知与字段从未出现保持区别。
- 无变化字段不增加历史、不覆盖来源；纯无变化补丁不撤销确认或增加版本。

这不是按城市、金额或问句写分支，也不推断用户语义。
既有旧引用拒绝、撤回、版本校验测试均保留。

验证过程：
1. 先新增两项回归测试，均出现`destination:cite_exact_current_message`错误。
2. 修改后测试通过，新增真实变化无证据仍拒绝的保护测试。
3. 使用上一批真实失败提案“珠海住宿628改582、审批未知”原样重放：
   原来失败，修复后7项检查全部通过，未重新调用模型。
   此结果是同提案的程序回归，不是一次新的模型理解成功。
4. 全量299项，278通过、21数据库跳过，7.872秒。

## 假设候选

文件：`scripts/typed_scenario_experiment.py`，不在生产图中导入或执行。

沿用SlotTask和ExpensePatch。expense保留实际陈述，scenario表示同笔费用的假设覆盖。
通过现有stage_submission在一次性副本上校验，返回基于哪个事项版本的假设；
副本不写入slots、不携带用户确认或企业核实元数据。

目前只支持本轮政策假设，未支持多轮假设档案、多个假设分支、政策子Agent消费和最终回答。
模型仍需判断内容应进入哪个区，程序分区无法证明归类正确。
本次真实对照没有启用独立复核或修复重试，不代表生产完整提取链的通过率。

### 新题逐轮

1. “核对我2026年12月3日在苏州的住宿，实际支付人民币347元。”
   两策略均正确建立实际事项，通过。
2. “针对刚才这笔住宿，只假设房价变成人民币623元，其他条件沿用，实际支付金额没有改。”
   typed提出scenario=623，但重复提交实际日期、城市、金额及旧轮引用，被拒绝。
   direct也重复实际字段，被拒绝且无假设分区。两者未通过。
3. “现在更正实际付款：人民币329元，其他实际信息不变。”
   两者提出329但重复其他旧字段；typed还提交旧轮证据，两者被拒绝。
4. “我只是在研究住宿报销条件，没有住宿支出。假设每晚每间含税价为人民币721元，能报吗？”
   typed把721、币种、计价单位、含税标记同时放入actual和scenario；direct放入actual。
   两者均被机械层接受，但语义不符合预期。明确未修复。
5. “检查我的机票政策，我的乘机申请明确没有获批；另请推演同一申请获批时的政策，审批实际仍未通过。”
   typed正确分出false/true，但transport_mode缺引用而拒绝；
   direct拆成两项并缺transport_mode引用，两者未通过。
6. “刚才关于我实际乘机申请未获批的说法撤回，我现在不知道审批结果，按未知状态核对。”
   typed提出null、direct提出false，但两者都缺transport_mode引用，未提交；
   前轮也没有成功建立事项，存在级联影响。不能说typed已实现正确跨轮延续。
7. “算一下我的差旅餐补：我早饭晚饭自己付款，只有中饭由接待单位免费供应。同行的人三餐都是接待单位承担，不要算到我头上。”
   两者covered_meals只有lunch，通过。本题不是此前错误提案注入复核题的重测。

## 验收工具自身修正

新题第四题误写了不存在的tax_included字段，真实合同为taxes_confirmed。
这是测试编写错误，不归因模型。修正后增加调用前字段名校验，避免再次付费运行非法预期。

原始`results.json`包含当时预期、源文件哈希和响应，保持不变。
`scripts/rescore_slot_results.py`只对原响应重新计分并记录修正后数据集哈希，未调用模型。
输出`rescored.json`；新题两策略依旧2/7，不因修正而变成通过。
