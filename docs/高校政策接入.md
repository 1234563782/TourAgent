# 高校政策接入

## 业务范围

系统提供高校差旅参考规划、政策解释与报销条件核对。用户自行到服务平台预订。
不办理审批、支付、下单、报销提交或保险理赔。原条款里的批准条件仍需解释，
但用户陈述“已批准”不是学校系统核验记录，系统不产生批准结论。

按项目所有者指定，所给合肥工业大学资料作为2026年项目采用政策。
这是项目口径，保留原文件发布日期，不宣称已外部核实其2026年法律效力。
管理员最近发布的版本就是当前采用政策；聊天不向用户询问政策生效时间。
需要更换制度时，由管理员核对并发布新版本，不由用户出差日期选择旧版本。

## 两份文件如何进入系统

原件归档于 `policies/hfut-2026/`：

- `合肥工业大学差旅费管理办法.docx`：正文和交通标准表。
- `P020160413407739028766.xls`：住宿标准附件。
- `lodging-sheet.json`：XLS只读提取快照，保留单元格来源。
- `manifest.json`：文件清单、政策键、生效范围、表头与行列布局。
- `reviewed-rules.json`：根据条款整理的可执行规则及来源映射。

Word按条款与表格行解析，不把全文当作一块。Excel仅导入Sheet1标准，
不导入Sheet3的修改建议调查表。合并单元格的省份只在同一编号组内继承，
不盲目把上一行所有空白填满。金额、单位、季节及区域从数据中读取，不写在问答代码里。

当前资料包含137分块：正文及交通表51块、住宿附表86行。
两个原件有各自文件哈希，整个资料包有统一哈希和版本。

## RAG与精确查询

1. 政策解释：问题经向量与中文关键词混合检索，补充相关条款，模型据此解释。
2. 住宿标准：已明确住宿事项、目的地、档次后，从同版本住宿表精确查询。
   当地该档次没有季节差价时不要求日期；有差价但未提供实际入住日期时返回缺失条件，
   不以今天替代。命中行仍加入RAG证据，模型说明适用条件，不凭印象算旺季。
3. 费用核对：结构化事实进入学校规则核验器，输出适用标准、缺失条件或超标信息。
   模型不能直接修改核验结果或将其称为批准。
4. 输出前：引用必须逐字存在于已检索原文，另作语义复核。回答、追问与补检索分别审核。

模型不直接打开用户桌面的Word或Excel；运行时读取数据库中已解析、已发布的数据。
原件用于追溯和重新导入。检索证据必须属于同一组织、政策键、版本和资料包哈希。
住宿精确查询仅在行来源已进入证据、实际业务日期一致（包括都未知）时参与解释，
不能替代原文引用。`expense_date`仅表示实际或计划费用/入住日期；“按2026年的政策”
不产生业务日期。一般咨询、撤回日期后的制度介绍都可正常检索。

当前真实问答还有一个限制：精确住宿检索分支依赖已提取的费用分类 `kind=hotel`。
本轮政策咨询实录出现该字段遗漏，即使目的地、日期、档次齐全，也可能仅走普通混合检索。
因此，结构化查询的离线与数据库测试通过，不等于真实政策问答始终触发了精确查询。
旧轮次曾重复索要日期；本次已移除政策日期默认值、历史继承与撤回阻断机制，
仍需真实模型验收，不能把提示词约束当作永不重复追问的保证。

追问允许缺少答案，不能因为用户尚未提供追问的信息而拒绝追问。
提案或引用失败默认最多尝试2次，可通过 `TRAVEL_POLICY_RAG_MAX_ANSWER_ATTEMPTS` 配置为1-3；
始终不放宽引用校验，不重试供应商错误。检索次数另由 `TRAVEL_POLICY_RAG_MAX_RETRIEVALS` 限制。

## 高校业务边界

- 学生、教职工、受邀人员身份与学术职称、岗位等级分别保存；登录角色不等于政策待遇。
- 交通一二三类与住宿部级、司局级、其他人员是不同体系，不相互推断。
- 住宿标准是元/人·天。仅有每间每晚房价时，单人入住等条件核实后才可对应；
  多人合住不能自动除以人数，也不能套原企业双床倍率。
- “其他人员档/档次/标准”仅规范化到资料中已有的“其他人员”表头；不把教授或交通二类映射进去。
- 旺季保留适用地区与月/旬边界；未知市县不擅自归入“其他地区”。
- 条件不足就保留未知；酒店含税、每晚口径或日期库存未经供应商明确核实，不认定预算合规。
- 会议统一安排且费用自理的例外、学生适用条件、科研超标说明等按原文解释。
- 补助核验仅覆盖所述单日一般标准，不自动计算连续在途超过12小时等特殊追加补助。
- 交通意外险的购买报销规定不是保险合同，没有保单不能认定具体事故是否赔付。

## 导入与切换

高校部署使用 `TRAVEL_POLICY_BACKEND=pgvector`。账号和政策库属于当前学校部署，
不再要求调用方提供组织 ID。政策键为 `hfut_travel`，
版本为 `2026-project-v1`，资料包保留2026-01-01至2026-12-31元数据用于管理追溯，
运行时不按这个范围拒绝查询，不将它当作用户出差日期。

在项目根目录使用既有 `.venv` 执行，输出包必须选不存在的新路径：

```powershell
.\.venv\Scripts\python.exe scripts/policy_admin.py prepare-package --manifest policies/hfut-2026/manifest.json --output <新资料包路径.json>
.\.venv\Scripts\python.exe scripts/policy_admin.py init-db
.\.venv\Scripts\python.exe scripts/policy_admin.py stage --bundle <新资料包路径.json>
.\.venv\Scripts\python.exe scripts/policy_admin.py publish --document-id <stage返回ID> --reviewed-sha256 <核对过的资料包哈希>
```

`prepare-package`纯离线；`stage`会将分块发给已配置Embedding服务并写草稿，
`publish`显式发布。不要将这里的占位符原样运行。修改原件或规则后必须重新生成并核对，
不能只修改数据库金额绕过资料包哈希。已有发布版本不能静默覆盖。

发布学校资料后，将 `.env` 的 `TRAVEL_POLICY_KEY` 切为 `hfut_travel`，
确认没有运行中的请求再重启 Web。不要更改已有密钥。
学校核验器与旧企业核验器按资料包profile分派，旧政策保留用于历史追溯与回滚，
不是学校政策缺失时的自动回退。

切换后新开会话。历史会话与行程仍是历史记录，不批量修改其事实、引用或结果；
如在旧事项上要求重新核验，将使用当前发布政策，并保留原事项的真实业务条件。
旧默认政策日期不再传给模型；已保存的历史答复不自动改写。

本次部署已发布文档ID 2，并将正式配置切换为 `hfut_travel`，8000服务已重启。
旧历史政策不是学校政策缺失时的自动回退。

需显式提供本机Node、依赖目录与浏览器路径；使用临时账号、真实模型和正式只读政策。

测试通过只证明覆盖场景，不保证任意自然语言表达或外部服务永远可靠。
