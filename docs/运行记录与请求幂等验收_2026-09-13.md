## 结论

本批范围通过：运行记录、按请求 ID 去重、重复结果固定回读、状态查询、
断流后刷新恢复及失败/中断会话门禁。正式配置的 PostgreSQL 已增加 `chat_runs`，
本地 `127.0.0.1:8000` 服务已重启，未修改 `.env`、账号、旧消息或长期偏好。

这不代表整个改造方案、任意自然语言理解或所有真实供应商查询全部验收通过。

## 实现范围

- `business_travel/chat_runs.py`：身份隔离的运行表、请求摘要、阶段及检查点引用。
- `business_travel/web.py`：聊天请求必填 request_id；同 ID 同内容回读原终态，
  同 ID 不同动作拒绝；确认继续校验 revision；HTTP 与 SSE 共用 graph.stream。
- 新运行状态 GET 接口检查登录及会话归属，只返回白名单，不回传内部输入或异常。
- 前端断流后不自动发送；刷新先读运行状态，再读取已提交会话，校验归属及终止状态一致性。
- 初始化脚本增加 `init-runs`；原无 request_id 的请求格式不再支持。
  `/api/chat` 路径仍指向原 web 会话，但没有独立的旧执行实现。

| --- | --- | --- |
| 隔离图发送“断流恢复验收”，截去 SSE done | 先禁止发送；刷新恢复“收到：断流恢复验收”，问题仅一条，已发送草稿清空 | 通过；该回答为测试图回显，不计自然语言质量 |
| 状态接口注入 running | 页面显示查询阶段，可刷新但不可发送；恢复真实接口后答案可读 | 通过；数据库并发另由真实 PG 测试覆盖 |
| 状态接口 interrupted、历史接口 completed | 首轮错误开放输入框；修复一致性校验后保持阻断 | 首轮未通过，修复后相同断言通过 |

真实查询没有预订、付款、审批或保存行程。表核验仅输出存在性、列数和运行聚合，

## 尚未完成

1. 不是模型逐 token 输出，仍是执行阶段和已完成任务的回答增量。
2. 检查点与运行终态不是原子事务；中间故障只能待核实，没有自动对账或重放。
3. 没有杀死真实执行进程或断开正式数据库做破坏性测试。
   锁连接丢失不证明外部调用已停止，不能宣称跨系统 exactly-once。
4. CLI 等可信本机工具不共享网页执行协议；不要并发操作同一网页线程。
5. 运行记录暂无保留清理策略，也未做负载、连接池或长时间稳定性测试。
6. P2 跨轮阻塞任务恢复/通用取消、P3 上下文预算和 P5 扩展真实质量评测仍需继续。
