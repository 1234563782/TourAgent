# 多人资源与调用配额验收

日期：2026-09-16。范围为风险清单第三项，不改酒店供应商、RAG检索或记忆语义。

## 实现

- 用户、公司、全局并发槽位和有界等待，使用共享PostgreSQL锁。
- 用户/公司每日请求与模型调用配额，原子预留和保守结算，单请求调用上限。
- 幂等回读不重复扣额，前置拒绝不创建failed运行。
- 复用官方连接池，拆分长会话和短SQL连接，清理会话锁、schema及事务状态。
- 流式接口保留前置429响应头；网页保留草稿，不把未执行请求误判为失败会话。
- 启动缺配额表时明确阻断；管理命令支持幂等初始化。

配置、执行顺序、表结构与计费边界见 `多人资源与调用配额.md`。

## 如何验收

测试使用本地 `.venv` 和现有pip依赖。新增 `test_resources.py`、
`test_resources_live.py`，不使用测试问句分支修改业务行为，不删除旧断言。
真实PostgreSQL测试使用随机独立schema，结束后删除；多进程测试真正启动第二个Python进程。
浏览器通过真实鉴权和API访问独立服务，模型使用确定性图，不产生模型供应商费用。

| 检查/问题 | 实际行为 |
| --- | --- |
| 一个用户在不同会话同时发送？ | 后一条429，已有请求继续，不新增失败记录 |
| 另一个用户是否被个人上限影响？ | 不受影响；仍受公司和全局上限约束 |
| 另一个Python进程能否绕过上限？ | 不能，返回user_concurrency |
| 公司或全局满载？ | 有等待名额时等待，超时拒绝；队列满立即拒绝 |
| 释放名额后等待者如何处理？ | 自动取得执行名额，进入原有执行流程 |
| 两个用户同时竞争最后一次公司额度？ | 仅一个成功，另一个daily_quota；事务无超扣 |
| 用户额度不足时，公司是否误扣？ | 整个事务回滚，公司计数不变 |
| 失败的模型调用是否被当成免费？ | 不会，计入已尝试调用；仅退未用预留 |
| 绑定工具、重试和并行图会否绕过本轮额度？ | 共享线程安全预算，超过上限不调用底层模型 |
| 连接断开怎么办？ | 释放槽位，未结算预留保守保留，后续模型调用拦截 |
| UTC跨日执行？ | 退回准入日预留，不更改新一天计数 |
| 重复request_id回读？ | 不执行图、不再计请求额度 |
| 连接池归还后还有旧锁、旧schema吗？ | 实际同一backend重借验证，无旧advisory锁或旧search_path |
| 事务异常或长连接耗尽？ | 事务回滚；等待超时有界，短查询池仍可用 |
| 未初始化配额表就启动？ | 明确报init-resources操作提示，不泄露DSN |

## 浏览器问题与回答

不是自然语言质量评测；以下为确定性执行和页面状态检查：

1. 提问“合成正常请求”，回答“收到：合成正常请求”，运行completed。
2. 同账号再次发送“保留这条未执行的草稿”，返回：
   “今日请求或模型调用配额不足。本次尚未执行，请等待配额重置或联系管理员。”
   保留草稿，输入/发送可用，移除尚未执行的临时气泡。
3. 刷新仍保留已完成记录和未发送草稿，没有failed运行。
4. 新建会话发送“新会话也不能绕过个人配额”，继续429，新会话没有运行记录。
5. 另一账号发送“另一用户独立额度”，请求200，不受第一个账号个人限额影响。
6. 1440及390宽度无横向溢出、无JS异常。已人工查看390截图，提示和输入框无重叠。

## 未验证或未实现

- 没有做高并发长时间容量压测，不承诺生产吞吐量或无饥饿公平性。
- 没有精确人民币费用预算，不覆盖embedding、MCP、地图等独立计费。
- 没有故障切换或强杀真实模型/订单供应商测试；模拟连接丢失不等同完整网络分区演练。
- 预留过大时会保守拒绝仍有少量剩余额度的请求；进程崩溃后未用预留不会自动退还。
- 多进程共享需要同数据库/schema及一致配置。非聊天接口的防滥用和历史配额归档不在本批。
