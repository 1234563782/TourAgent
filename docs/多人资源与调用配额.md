# 多人资源与调用配额

## 范围

所有经过鉴权的 HTTP 聊天入口默认启用同一套资源保护，包括同步、流式、原有 web 会话、
新会话及确认操作。身份来自服务端登录态，不能由请求体指定公司或用户。
本机可信 CLI、离线导入和管理脚本不计入聊天配额。

生产代码为 `business_travel/resources.py`、`db_pool.py`；配置入口为 `settings.py`。
不引入 Redis 或额外队列服务，使用现有 PostgreSQL 和已经安装的 psycopg-pool。

## 执行流程

1. 验证会话归属、取得会话锁、读取运行记录和检查点。
2. 已完成的相同请求直接回读原结果，不占执行槽位，不重复扣额度。
3. 校验新消息或确认版本，再申请用户和全局槽位。
4. 用户并发已满则直接拒绝。全局容量满时进入有数量和超时上限的等待队列。
   等待期间不调用模型、不创建运行记录。该队列不承诺严格 FIFO，也不会持久化等待请求。
5. 原子检查并扣除用户、公司每日请求额度，同时预留本轮最多可用的模型调用次数。
   任一范围不足，整个事务回滚，已申请的槽位释放。
6. 准入后创建运行记录、执行原有图。每次真实模型 invoke 前检查当前连接及本轮调用预算。
   包括绑定工具、结构化重试、子 Agent 和图并行线程；供应商 SDK 隐藏重试原本已关闭。
7. 正常退出或可处理异常均结算已尝试调用数，退还未使用的预留；释放槽位。
   进程崩溃、连接中断或退款提交结果不确定时，不自动退款、不重试退款，保守保留预留。

重复请求的范围仍是原有“公司、用户、会话、请求 ID”，不是跨会话去重。
准入后的请求即使模型调用失败，也消耗一次请求额度；已尝试模型调用不退款，因为供应商可能计费。
未通过上下文长度门禁的调用不会进入模型调用计数。

## 持久化与隔离

在配置的记忆 schema 内新增 `resource_daily_usage`，默认完整表名为
`travel_memory.resource_daily_usage`。主键包含公司、统计范围、主体和 UTC 日期。

- 公司和用户额度在同一事务内更新，并使用固定加锁顺序防止反向争锁。
- 日期来自数据库时钟，不依赖各 Web 进程的本机日期。每天 UTC 00:00 使用新一行；
  跨日执行退回准入日期的预留，不改新一天的计数，无需定时清零。
- 会话、用户、全局执行和等待槽位使用会话级 advisory lock，持有连接退出后释放，多个进程共享。
- 当前单校部署只保留一个全局执行容量；company_id 仍用于学校级每日配额和身份隔离，不再作为并发槽位维度。
- 全局范围是同一个 PostgreSQL 数据库和记忆 schema。不同数据库或 schema 不共享额度。
- 同一服务集群必须使用一致的并发阈值；更改阈值应先排空请求，再统一更新全部进程。
- 每日记录当前不自动删除。保留与归档周期需按公司的审计要求另行确定。

## 配置

完整示例见 `.env.example`；真实 `.env` 未填写时采用以下默认值，无需新增密钥。
修改后需要重启，不能在线混用不同阈值。

| 环境变量 | 默认值 | 含义 |
| --- | ---: | --- |
| TRAVEL_RESOURCE_USER_CONCURRENCY | 1 | 同用户执行或等待中的请求数 |
| TRAVEL_RESOURCE_GLOBAL_CONCURRENCY | 8 | 同数据库/schema执行数；单校部署唯一的系统执行容量 |
| TRAVEL_RESOURCE_QUEUE_SIZE | 8 | 额外等待名额，0表示不排队 |
| TRAVEL_RESOURCE_QUEUE_TIMEOUT | 2 | 等待秒数，支持小数 |
| TRAVEL_RESOURCE_POLL_SECONDS | 0.05 | 检查可用槽位的间隔秒数 |
| TRAVEL_RESOURCE_USER_DAILY_REQUESTS | 100 | 用户每日准入请求数 |
| TRAVEL_RESOURCE_COMPANY_DAILY_REQUESTS | 1000 | 公司每日准入请求数 |
| TRAVEL_RESOURCE_USER_DAILY_CALLS | 2000 | 用户每日模型调用额度 |
| TRAVEL_RESOURCE_COMPANY_DAILY_CALLS | 20000 | 公司每日模型调用额度 |
| TRAVEL_RESOURCE_REQUEST_CALLS | 24 | 单次请求模型调用上限及预留数 |
| TRAVEL_DB_POOL_SIZE | 12 | 单进程每个数据库的短查询池上限 |
| TRAVEL_DB_SESSION_POOL_SIZE | 36 | 单进程每个数据库的长会话池上限 |
| TRAVEL_DB_POOL_WAITING | 16 | 每池最多等待连接的调用者数量 |
| TRAVEL_DB_POOL_TIMEOUT | 5 | 获取连接最长等待秒数 |

用户并发不得超过全局并发。长会话池至少为
`2 * (全局并发 + 等待名额) + 2`，用于会话锁、checkpoint和读取余量。
配额不足以预留完整的单请求上限时，即使尚有少量剩余额度，也会拒绝新请求，这是保守准入策略。

## 数据库池

长时间占用的会话锁和 checkpoint 使用长会话池；鉴权、运行记账、记忆和政策 SQL 使用短查询池。
两者独立，排队请求不能占满运行记账需要的短连接。
使用有界等待、获取连接超时、连接检查、退出关闭和归还时 `DISCARD ALL`。
每次借用都显式设置 schema，异常事务回滚，禁止复用旧锁或旧会话设置。
政策事务明确使用 public schema；连接器注入仍可用于离线协议测试。

池是单进程的，而业务槽位与配额跨进程共享。部署前要计算
`进程数 * 各数据库各池上限 + 其他服务连接数`，不得超过数据库允许连接数及预留空间。
这里的默认值用于本项目单进程受控试用，不是多人生产容量承诺。

## 前端与失败边界

准入拒绝返回 HTTP 429、`Retry-After`、`X-Travel-Admission: rejected`。
网页仅在收到这组明确证据时移除临时气泡、保留输入、允许稍后手动重试，不自动重发。
配额不足也不会产生 failed 运行，新建会话不能绕过个人每日额度。

执行中途达到调用上限则与准入拒绝不同：停止后续模型调用，保留失败记录并要求核实/恢复。
浏览器断开仅停止推送，服务器仍完成已有执行及结算，不因断流提前释放资源。
连接断开后新的模型调用会被拦截，但已发出的外部请求无法承诺立即取消。

这不是精确金额预算：不包含 embedding、MCP、地图、天气等外部服务的独立账单，
也没有实现按模型单价、缓存价格、退款或供应商账单对账。调用次数配合原有单次上下文/输出预算，
提供费用增长的防护边界，不能宣传为精确人民币限额。
会话创建等非聊天接口的业务限额、严格公平队列、压力容量及数据库故障切换需另行治理。

## 部署与验证

停止接收新请求、核实没有 running 执行后，进行幂等初始化并重启服务：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\auth_admin.py init-resources
```

全新环境原有 `init` 会同时创建配额表。启动会验证表是否可读，缺表不会绕过资源保护继续运行。

```powershell
$env:TRAVEL_TEST_POSTGRES='1'
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -q
.\.venv\Scripts\python.exe -m pip check
```

`scripts/verify_auth_browser.py --resources` 使用隔离账号、schema和测试图做网页验收；
还需按脚本帮助传入本地 Node、node_modules 和浏览器路径，不使用正式账号或真实付费模型。
