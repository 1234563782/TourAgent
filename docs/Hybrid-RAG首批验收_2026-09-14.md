## 本次实现

1. Word 正文优先沿句末切分，超长单句保留硬上限；通过已有 `related_ids`
   关联同一段落分片、同章同条款内容。支持中文条款与多级数字编号。
2. 关联检索执行有界传递补全，防止循环；缺失条款或超出片段预算时标记依据不完整。
3. 政策解释生成 `PolicyAnswer` 工具参数，用 Pydantic 校验动作互斥及字段结构；
   对每条结论校验来源编号和原文连续摘录，再通过独立 `PolicyAnswerReview` 调用复核。
4. 缺用户信息时输出经复核的追问，并将任务标记为待补充；已有来源不足时允许有界改写。
   总检索默认最多两次，保持原问题、公司、政策键及适用日期，不跨版本合并证据。
5. 对来源无版本、上下文缺失/超限、服务异常、畸形检索响应、非法工具调用保守结束。
   不返回未校验结论，不透传任意服务错误原因；保留无适用已发布政策的明确中文提示。
6. 接入既有执行阶段事件和中文来源展示；个人费用核验仍使用已审阅确定性规则。

相关代码：`business_travel/policy_documents.py`、`policy_pg.py`、`policy_rag.py`、
`policy_guard.py`、`graph.py`、`tasks.py`、`execution_events.py`、`settings.py`。
配置与使用说明见 `docs/policy-rag.md`、`.env.example`。

## 问题、回答与拦截

以下回答来自**脚本模型预设输出**，用于检查流程是否允许或阻止发布，不是真实模型作答记录，
也不表示系统遇到这些问题时总能正确理解。生产逻辑不按这些问句匹配或返回固定答案。

| 输入或注入场景 | 预设提案 / 实际程序结果 | 验证结论 |
| --- | --- | --- |
| “住宿费用按什么单位核对？”；来源为“住宿费按每间每晚含税金额核对。” | 提案“住宿费核对的是每间每晚的含税金额。”；引用核验和复核通过后显示结论、`[S1]`及文件/版本/条款 | 带证据结论可发布 |
| 图输入“请解释2026-09-14的住宿费用计价标准” | 同上；最终任务为 `completed`，未调用费用核验 | 政策解释入口已接入 |
| 同一图输入，注入追问提案“请问是哪个职级？”并让复核接受 | 输出追问，任务为 `needs_clarification` | 验证追问状态流转，不证明该问题确实需要职级 |
| 引用不存在的 `S9`、摘录不存在的“每晚100元”或空白摘录 | 不发布“伪造结论”，不进入语义复核 | 引用存在性门禁有效 |
| 有合法摘录，但复核返回 `reject` 或 `conflict` | 不发布结论；冲突显示中文待核实提示 | 复核否决不会被忽略 |
| 改写为“住宿计价单位与税费”，复核接受 | 最多再检索一次，仍使用原问题与原适用日期 | 有界补检索与日期约束有效 |
| 重复原查询或改写被复核拒绝 | 不再检索；预算耗尽也停止 | 不发生无限循环 |
| 第二次来源变为另一版本 | 返回 `version_changed`，不生成混合版本回答 | 阻止重查期间版本混用 |
| 关联片段缺失、循环、超过片段/字符预算 | 循环终止；不完整依据不生成回答 | 上下文预算与完整性门禁有效 |
| 模型输出自由文本 JSON、多次工具调用、额外公司字段 | 不发布结论 | 不靠提示词后解析任意 JSON |
| 检索返回错误类型或异常含私密 URL | 不崩溃、不输出敏感错误原文 | 异常边界与脱敏防护有效 |

还覆盖无版本来源、来源去重、不发送重复完整表格网格、句子字符无损、
同章条款关联、跨章节重复编号隔离及配置上下限。

## 限制与下一步

- 解释与复核目前复用同一模型配置，是独立调用而非不同模型；无法保证消除共同判断错误。
  原文摘录存在也不等于语义必然正确，需要真实问题验证例外、否定、适用范围与多轮追问。
- 关联补全可能放大上下文并导致保守拒答；字符预算不是 token 预算，未实现自动压缩。
  空结果或服务失败不自动改写，补检索只作用于已取得完整来源的情况。
- Word 表格按首行表头展开，多级/合并表头需要人工核对；不是通用复杂版面或语义分块引擎。
- 新分块不会自动更新现有已发布资料。先确认版本及生效日期，显式 prepare，
  人工核对关联与表格，再 stage/publish；不能为技术重建随意改变政策生效时间。
- 下一阶段先核验真实数据库和模型端到端问答，再评估是否引入独立 reranker。
  不以本轮脚本测试推断重排收益，不自动覆盖版本、修改真实配置或发布政策。
