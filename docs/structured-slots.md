# 结构化槽位与受控工作流

## 提交协议

入口采用按需分阶段 Tool Calling；每个阶段只绑定一个指定工具，工具本身不查询、不保存、不下单：

1. `TurnRoute`：识别新建、修改事实、切换目标，以及取消、继续和失败轮恢复；只选择事项/任务，不提交领域事实。
2. `TripExtraction`：仅当存在规划事项时，批量提取全部规划事项的差旅字段。
3. `ExpenseExtraction`：仅当存在政策核验或制度解释时，批量提取全部费用事项字段。
4. 后端组装内部 `SlotSubmission`，统一证据校验、独立语义复核和原子提交。

`task_index` 绑定本批任务，每个已分配索引必须恰好返回一次；缺失、重复、跨领域或额外索引拒绝。
闲聊、偏好/记忆请求及已有结果解释使用 `other`，不加载差旅或费用字段schema。
路由可以在目标/语义确有歧义时返回追问，但不得同时提交变更；缺日期等业务必填字段由工作流追问。
同领域多个事项只进行一次字段提取，不按事项数逐一调用。

沿用现有 `langchain-core`、`langchain-openai` 的 `bind_tools` 和 Pydantic；
这是自定义受控提交流程，不是直接调用高层 `ToolStrategy` 类。

先检查调用数量、工具名称和 schema，再检查当前用户原话证据、事项 ID 与版本。
不从普通文本里截取 JSON；工具调用解析失败、模型超时或重试耗尽时停止业务派发。
只返回脱敏错误类别，不把异常原文或密钥发给用户。

`TurnRoute.tasks` 支持有上限的任务队列；组装后每项内部任务的 `expense` 与 `trip` 互斥：

- `operation=new_task` 创建事项并指定intent，不继承旧条件，也不能提交旧事项引用。
- `operation=update_facts` 仅提交本轮事实变化；协议不允许intent字段（包括null），服务端继承原任务目标。
  领域补丁必须至少提交一个字段；空更新被机械拒绝，不能作为保持待办或继续执行的替代入口。
- `operation=change_intent` 才能切换目标，必须提供新intent及当前原话支持的intent_change_evidence。
- 两种更新选择target_id；同事项多个目标时必须提供target_task_id。base_revision由后端从本轮可信快照绑定，
  并在协调提交时再次校验，不允许模型提供版本、状态或执行次数。
- 同一批只允许更新同一事项一次；引用过期或取消时拒绝，目标歧义时追问，整批不执行。
- 字段省略保留原值；`null` 必须有明确撤回或“不确定”等原话。
- 任一字段失败，整个补丁不提交；通过后旧核验结果失效。
- 日期及明确布尔条件遗漏可触发模型补交，不由检查代码猜值。
- `evidence` 的键是字段名，值是各自的 `{quote, user_message?}` 对象；不能把quote直接放在字典根部。
  schema错误反馈解释省略多余字段及对象结构；反馈不是用户事实，后端不自动改写模型提案。
- 同一补丁明确给出一间房、成人总数和完整儿童年龄列表时，检查每房人数是否遗漏或与总人数矛盾。
  拒绝后由模型根据授权原话重新提交并接受复核，不由后端补人数或伪造证据。
  多房、儿童信息未知、显式撤回以及跨轮分散提供的条件不在此有限检查范围内；不平均分房。
  该结构检查不替代语义复核，不能证明所有原话信息都已提取。

路由及领域提取使用同一份深拷贝快照。任意阶段失败都不发布部分事实；重试从路由重新开始，
受 `TRAVEL_SLOT_MAX_ATTEMPTS` 与请求模型调用额度共同限制。修复反馈不是事实或用户授权。
旧模型工具没有回退兼容；`SlotSubmission` 仅是后端内部契约。固定原子提案的转换只在脚本测试夹具中使用，
不分析用户问法、不进入生产模型解析流程。协议拒绝行为另用未经转换的原生工具响应测试。

不计下游业务与重试，常规成功路径的入口模型调用数为：闲聊/控制2次（路由+复核），
单领域3次，双领域4次。路由直接追问只调用1次。每阶段仍执行输入预算和资源配额检查。
实测三个工具定义的紧凑UTF-8 JSON估算分别为5418、4435、5393字节；旧工具实测33470字节。
这些数字不是真实token、总输入量或费用；历史/状态会重复传入，不能据此宣称总延迟或总费用下降。
Langfuse以 `slot_protocol.slot_phase` 区分阶段，调用预算观测继续记录真实usage及估算偏差。

“元”不能直接证明人民币，“一晚”不能直接证明每间每晚。
短引用可以扩展到同一原文分句验证，但不拼接不存在的原话。
这些检查是保守规则，不是完整自然语言语义证明；复杂否定、引用、多事项需继续验证。

## 主子分工

政策检查直接使用已验证槽位构建 `ExpenseFacts`，调用确定性规则引擎。
制度解释走混合检索、结构化回答、逐条原文引用验证与独立复核，再由代码展示。
不让解释模型重新提取业务事实或改写确定性规则结果。
遇到特批转人工核实，不自动批准；缺条件则补问。

规划按已校验的查询契约确定组件，再用 `PlanSelection` 选择真实候选 ID。
车型过滤和时间优先排序在途牛返回页截断前进行；这不代表已翻遍所有供应商页面。
重复、虚构 ID、同一组成部分重复选择和已知时间冲突被拒绝。
选择失败保留真实候选和失败状态；有冲突的组合记录原因，不当作完整草案。
价格、库存、含税口径及预算不能确认时保持未核验。

主助手调用通用记忆、天气、保存确认及只读任务结果工具。政策和规划结果由代码呈现，
避免模型把“信息不足”改写为“合规”。保存偏好、草案仍需 LangGraph interrupt 确认。

### 已有结果追问

对已返回候选、核验结论、缺失信息的追问，没有新增事实或重新执行要求时，
通过无领域补丁的 `other` 委派给主助手，并调用 `read_task_result(task_id, expected_revision)`。
不把历史行程条件重新抄成费用事实，不把供应商报价认定为用户的实际支出。

工具只读取当前身份绑定会话检查点中的任务及事项结果，核对任务、事项、结果引用和版本，
拒绝未知任务、过期版本、已取消或执行中的任务，以及不匹配的领域和未复核事项。
不重新调用供应商、RAG、费用规则或写入偏好；普通本轮对话及任务记录仍按既有机制持久化。
输出沿用受控结果渲染，明确是历史快照，不代表当前库存、最终房价或审批通过。
指代有歧义时应询问目标；新的费用、新条件、明确重新核验或独立政策问题仍走业务工作流。

抽取器和独立复核器共享 `available_results` 最小摘要，复用只读工具的版本门禁，
包含任务引用、结果状态、候选数量和核验状态，不复制供应商正文或创建费用事实。
已保存的核验结论即使是信息不足，也可读取解释；未知状态本身不授权重新执行。

2026-09-15后续两批酒店验收各11轮/14项通过，最终批11条云端追踪、134个观测通过。
早期连接错误、HTTP500及路由失败记录仍保留，详见真实对话与Langfuse联合验收报告。
这些结果是已执行场景的证据，不把本地回归或有限真实问答等同于任意问法的正确性保证。

## 未提交请求恢复（2026-09-15）

模型提取、独立复核或提交前校验失败时，本轮原话仍在对话历史中，但不成为业务事实。
`AgentState.pending_turns` 只记录用户消息索引、消息ID、SHA-256指纹和业务版本，
不存未经复核的模型提案。它沿用按公司、用户、会话隔离的PostgreSQL检查点，
无需新表或新增环境变量，旧会话缺此字段时视为空。

模型通过 `TurnRoute.recovery` 提交，后端组装为 `SlotSubmission.recovery`：

- `action=retry|discard`：重新提取或放弃未提交请求，不是恢复已执行工具。
- `user_messages`：精确选择本会话待处理原话索引，不能引用任意历史。
- `evidence={quote}`：本轮用户授权的原文证据；当前user_message索引由后端绑定。

恢复过程先检查当前授权引用、待处理记录和事项版本，再从选中原话与本轮内容重新提取，
经过完整schema、事项归属、字段证据及独立语义复核后才原子提交。
当前更正或撤回优先；有歧义则追问，不复用旧提案，不自动选择最近一次失败。
恢复后字段证据指向实际原话索引，事项另记最近一次 `recovery_authorization`。
该字段不是独立完整审计事件表，业务历史和原始消息仍按既有机制保留。

普通历史仍不能作为新增事实引用。仅本轮明确授权且 `retryable=true` 的选中失败轮允许例外。
事项版本或业务任务状态/尝试次数改变时，旧待处理请求要求重述，避免覆盖新事实。
此门禁按会话内全部业务事项快照保守判断，无关业务事项的变化也可能要求重述。
闲聊不触发恢复、不清除记录；放弃只清选中的待处理标记，不删除对话、不取消任务。
单纯放弃允许 `tasks=[]`、`task_controls=[]`，返回确认后结束，不再派发。

待处理上下文最多展示最近 `TRAVEL_SLOT_CONTEXT_LIMIT` 条，未展示的较早请求需重述。
恢复失败保留原待处理项；成功只清选中项，其他项不会被自动重放或清理。
明确恢复历史偏好写入、保存、预订、确认等委派动作不在此协议范围，需重新发起普通授权流程。
已提交任务的继续/取消仍用 `task_controls`，不得与未提交事实恢复混淆。

19项恢复定向回归覆盖初次失败、多事项选择、当前覆盖、撤回、否定复核、歧义、
旧版本、短上下文、会话隔离及SQLite重开，另有PostgreSQL重开验证。
语义授权判断仍依赖模型复核；进程崩溃、已执行工具的结果未知和跨进程重放不在本次范围。

## 查询范围（2026-09-13）

新规划事项必须提交有当前用户原话证据的 `query_scope`，并经过独立语义复核。
不能根据缺了哪些字段猜查询范围；漏填范围进入有限重试，耗尽后停止派发。
用户意图有歧义时应澄清，不默认当成交通查询。

| 范围 | 执行契约 | 必需信息 |
| --- | --- | --- |
| `hotel` | `HotelRequest` | 目的地、入住日期、退房日期 |
| `transport` | `TransportRequest` | 出发地、目的地、出发日期 |
| `combined` | `CombinedRequest` | 交通必需信息及入住、退房日期 |

`journey=round_trip` 另需返程日期；`one_way` 不执行返程查询。
缺字段时追问，不调用供应商；酒店单查不会追问出发地或出发日期。
缺职级不阻止查询酒店，但涉及政策核验时保持信息不足，不自动认定合规。

范围修改继续走事项 ID、版本、原话证据和复核。执行请求排除不相关组件字段，
但不删除事项中的原事实。例如组合查询改成只查酒店，旧出发地仍存储，
却不会进入本轮查询或采用事实展示；旧草案失效，按新范围重建。
过去入住日期在供应商调用前拒绝，不用默认日期补齐。

旧 `TripRequest` 和默认交通执行回退已删除。无范围的历史事项在目标可确定时允许补充，
但执行前必须澄清查询范围；不能根据已有酒店日期改判意图。显式范围不能撤回为 `null`。
若旧检查点既无任务记录，也未记录目标，则保留原事实并追问，不猜测要延续哪个目标。

供应商适配器拒绝未请求组件；失败响应中的候选、组件或方向不匹配的候选不得入选。
展示区分“查询成功但无候选”和“查询失败或不可用”，两者都不是完整草案。
规划结果记录查询耗时、选择次数及选择/检查/总耗时，属于最小追踪，
不等于完整运行日志、实时事件流或真实质量基线。

## 持久任务（2026-09-13）

`AgentState.tasks` 保存服务端任务 ID、意图、请求文本、事项 ID/版本、状态、缺失字段、
前置任务 ID、结果引用和尝试次数。事实与工具结果仍以 `slots.subjects` 为准，不重复保存。
任务台账沿用原有按公司、用户、会话隔离的检查点，Web 快照只返回白名单任务字段。

- 缺信息进入 `needs_clarification`，不触发人工授权中断；闲聊不会清除它。
- 修改条件或显式切换目标复用对应未取消任务 ID；同批连续更正须归并为一个补丁，否则整批拒绝。
- 派发前校验事项版本；变更使旧结果引用及下游任务结果失效，不能借旧草案保存。
- `depends_on` 仅接受当前批次中更早的任务索引，经过语义复核后由服务端转换为任务 ID。
  前置任务必须 `completed` 才执行依赖项；空候选标为 `partial`，服务失败标为 `failed`。
- 独立任务分别记录结果，某项工具或助手模型失败不阻止其他独立任务；错误原文不展示。
- 保存及事实确认继续走原确认工具和版本门禁；待授权的任务标为 `awaiting_confirmation`，
  确认后根据真实工具结果完成，取消保存标为 `cancelled`，不代表取消供应商订单。
- 历史阻塞任务不会跨轮自动重放。明确恢复和取消使用下述控制协议，仍通过本轮提取和复核。

任务台账本身不实现上下文预算，也不保证真实模型不会产生语义错误。

## 多轮目标连续性（2026-09-14）

抽取器与独立复核器同时接收 `pending_tasks` 和 `task_context`：
前者只含未完成任务，供继续/取消控制；后者包含已完成任务的目标与事项版本，
供“修改条件后重新回答”使用，不直接授权重新执行。

- 回答追问或更正条件沿用原目标，完整事实不意味着从制度解释切换为费用合规核验。
- 问某个城市和职级的适用上限仍可属于 `policy_explain`；具体费用或待遇核验属于 `policy_check`。
- 更新事项若改变当前版本已有任务的意图，必须使用 `change_intent` 并提供
  `intent_change_evidence={quote}`；当前消息索引由后端绑定，`update_facts` 中带intent直接被schema拒绝。
  程序检查当前消息索引和原话；独立复核器判断原话是否真正请求另一种操作。
  引用存在不代表语义正确，不通过时整批不提交。
- `question` 应承接原目标并写成包含更新条件的独立请求，不能仅留下“我是普通员工”等孤立补充。
- `expense_date` 在制度解释中也表示明确指定的政策适用日期，不能只写在问题文本中；
  后续不改日期时保留原值，不回落到当天日期。
- 同事项切换目标也继续复用任务 ID，即使补丁为空也增加revision，记录goal_history，
  清除事实确认及结果引用，依赖该任务的结果同步失效。政策与行程跨领域目标需独立新建。
  本轮没有新建数据表、迁移既有会话或修改业务金额。

语义承接和遗漏识别仍依赖模型与复核；该门禁不是对任意自然语言的正确性保证。

## 日期来源与继承

- 政策解释使用事项中的policy_date上下文，保存实际日期、原始来源、选择方式及原话引用。
- 明确日期写入expense_date；只改城市或职级时沿用日期，来源仍为原用户陈述，不能标成新的用户事实。
- 未提供适用日期时，首次解释默认采用当天并固定在本事项；跨日更正条件也不偷偷切换到新一天。
  默认值不会写进费用事实，不能拿它补齐个人费用核验的必填日期。
- 显式null表示日期已撤回；直接追问并标记缺少expense_date，不再调用政策检索或默认今天。
- 旧结果有日期但无来源时保留日期并注明来源未记录，不补造原话。
- 回答显示实际采用的政策日期、来源及是否沿用。提取失败保留事实和台账，
  但沿用原安全策略清除可保存草案，避免误存旧方案。

只保留旧检查点读取；不兼容旧模型的action=new/update写协议，也不从普通文本JSON回退解析。
隔离实验的TypedSubmission不是生产接口，使用独立提示词；不会绕过正式复核和派发门禁。

## 跨轮任务控制（2026-09-14）

`TurnRoute` 同时支持 `tasks` 和 `task_controls`，由后端组装到内部批次；除明确授权的未提交请求
`recovery.action=discard` 外，至少一个非空，两者合计不超过 `TRAVEL_SLOT_TASK_LIMIT`。
只有控制操作时无需额外生成闲聊任务。

模型控制字段：`action=resume|cancel`、`target_id`、`evidence={quote}`。
后端从当前会话任务快照绑定 `expected_revision`、`expected_attempt`、`expected_status`，
从当前消息绑定 `evidence.user_message`；不允许模型填写这些执行元数据。
服务端校验原话确实存在于当前用户消息、任务身份和预期状态，再由独立复核器判断真实授权、
否定、假设和指代歧义；引用存在不等于语义正确。任何一项不通过，整批不发布。

- `resume` 仅恢复 `plan_trip`、`policy_check`、`policy_explain` 等只读业务任务。
  事项版本必须一致，依赖仍需成功；多个明确恢复项按依赖排序，不按模型提案顺序盲派发。
- 明确要求继续但仍缺必填事实时，仍提交 `resume`，由执行器追问，不因缺字段降为闲聊。
  仅保持现状、推迟决定或否定授权时，不提交控制；由无领域补丁的 `other` 正常回应，待办不变。
- 补充事实使用 `update_facts`，保留原依赖；同一批不能既控制又更新同一事项。
- 历史 `other` 可能包含写入，因此不能直接恢复；应根据当前明确的新请求重新走助手授权流程。
- `cancel` 终止未完成任务的后续调度，不撤销已完成操作、不退订、不删除已存数据。
  下游任务阻塞并说明前置取消，取消状态不会被后续事项更新复活。
- 取消后重新明确查询会创建新任务，保留原取消记录；不会把旧依赖自动接到新任务上。
- `running`、`awaiting_confirmation` 及已完成/已取消任务不能使用此协议。
  等待人工确认仍使用原确认按钮和检查点版本；不支持并发消息打断正在执行的供应商请求。
- 取消部分成功的查询清除当前可保存草案；事项历史和真实工具结果保留供核实。

无需增加数据库表或环境变量，随现有 PostgreSQL 检查点保存。详见
[跨轮任务控制验收](跨轮任务控制验收_2026-09-14.md)。

## 配置与存储

- `TRAVEL_SLOT_MAX_ATTEMPTS`：槽位重试上限。
- `TRAVEL_PLANNER_MAX_ATTEMPTS`：候选选择重试上限。
- `TRAVEL_LLM_EXTRA_BODY`：模型请求附加 JSON，按服务商能力配置。
- 官方 DeepSeek 地址的默认模型适配会关闭 thinking，以兼容本项目指定工具调用；
  这是本地请求探测后的适配，不表示所有服务商或所有模型都支持同一参数。
- 旧 `TRAVEL_POLICY_MAX_CHECKS` 配置保留兼容，新政策工作流不使用模型核验循环。

真实 `.env` 未因本次改造被覆盖，无需增加数据库种类。
正式 CLI 的槽位属于 LangGraph 检查点，随 PostgreSQL 的公司、用户和会话范围持久化；
偏好与历史行程仍由既有 PostgreSQL 记忆存储管理。测试使用独立 SQLite 或随机数据库 schema。
Web 已有登录态聊天与多会话接口，详见 `web-auth.md`。
现有 SSE 推送真实执行阶段和已完成任务回答增量，最终以终态检查点快照为准，不是逐 token 输出。
