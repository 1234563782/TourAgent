# 政策复核耗尽修复验收

## 问题与范围

用户问“我是院士，帮我查一下我的出差标准是什么”，真实链路已检索到资料，
模型也生成了部分答案，但连续复核返回 `incomplete_answer`。
旧代码在 `generate` 内重试耗尽后直接返回 `insufficient`，
没有进入此前仅为检索预算耗尽、重复查询设置的收尾。

本次修复控制流程和收尾审核协议，不增加身份专用规则，不改变政策数据、检索次数或模型配置。

## 实现

1. 普通语义复核耗尽后进入一次终止阶段，带上待修正草稿和反馈。
2. 终止生成使用 `PolicyFinalAnswer`，禁止继续检索。
3. 终止回答使用 `PolicyEvidenceReview`，逐条审核结论是否有来源支持；
   程序拒绝漏审、重复编号、越界编号、缺失安全字段和错误类型。
4. 将证据可靠性、限制说明、事项范围、完整性与冲突分开。
   部分回答可以不完整，但已展示结论与限制说明必须全部通过审核。
5. 不支持的结论编号传回有界修复；新草稿重新审核，不自动发布被拒草稿。
6. 终止阶段再次耗尽会停止，不递归收尾。引用错误、冲突、上下文或供应商故障仍单独处理。

代码中的收尾原因新增 `review_budget_exhausted`，可在 Langfuse 的 `policy_result` 查看。
启用内容观测后，终止复核工具参数中可以查看 `claim_checks`、
`limitations_valid`、`scope_preserved`、`coverage_complete` 和 `conflict`。

## 离线验证

新增用例先运行再修复，观察到9个失败子例，证实没有进入终止阶段。
修复后覆盖以下路径：

| 路径 | 验证目标 | 结果 |
| --- | --- | --- |
| 部分回答连续被拒 | 转收尾、保留重新审核通过的结论 | 通过 |
| 两轮检索后耗尽 | 复现原链路结构，保留同版本累计来源 | 通过 |
| 终止审核判定不完整 | partial 可通过，完整 answer 不可冒充完成 | 通过 |
| 结论无依据、限制不实、目标变化 | 不向用户发布 | 通过 |
| 漏审、重复或越界编号、错误类型 | 协议拒绝，不自动补成通过 | 通过 |
| 尝试上限分别为1、2、3 | 正常与终止阶段各自有界，不循环 | 通过 |
| 终止阶段引用错误、超时或冲突 | 保留独立错误类型、不盲目重试 | 通过 |
| 缺少必要个人条件 | 允许经过复核的针对性追问 | 通过 |

最终完整离线回归：853项，762通过、91跳过、零失败，22.091秒。
跳过的是需显式启用相应环境的用例，不能计为通过。
`pip check` 通过。测试命令：


## 真实服务验证

只读已发布政策库，使用已有模型配置，不写用户会话，不上传真实历史聊天。
验收脚本关闭自身 Langfuse 上报，结果保存在本地 `.verification/policy-review-exhaustion/`。

### 自然请求

问题：我是院士，帮我查一下我的出差标准是什么。

输入事实仅为身份，没有补造目的地或日期。结果为两次检索后的 `partial`：
保留交通待遇和随行条件，说明住宿档次无法确定，并要求提供目的地；
伙食补助、市内交通费标准仍列为未解决部分。
没有再把全部答案替换成“现有政策证据不足”。

证据：`original-question-live.json`。该次没有自然触发复核耗尽，
因此不能单独用它证明终止分支经过了真实模型验证。

### 明确标记的故障注入

同一问题，仅在测试进程中模拟普通 `PolicyAnswerReview` 连续返回
`reject / incomplete_answer`。不改变生产代码，不修改真实最终审核输出。
检索、生成和最终 `PolicyEvidenceReview` 均调用真实服务。

第一次注入两次普通拒绝后，返回 `partial`，
`stop_reason=review_budget_exhausted`，只检索一次；
真实最终复核对三条结论返回支持，对完整性返回否。
证据：`injected-review-exhaustion-live.json`。
这是受控故障验证，不是自然请求自行出现连续误拒。

定稿代码再次执行相同注入：两次模拟拒绝后，真实最终审核仍对三项结论返回支持、
对完整性返回否，结果为 `partial / review_budget_exhausted`，
没有新增检索或循环。证据：`final-injected-review-exhaustion-live.json`。

## 边界与剩余问题

- 首次沙箱内真实调用在检索阶段不可用，保留为 `original-question.json`；
  申请沙箱外读取权限后成功，不通过修改凭证或跳过鉴权解决。
- 本轮真实结果尚未完整召回伙食补助和市内交通费条款，不能宣称综合待遇回答已全部完整。
- 故障注入结果中的核实建议仍有改进空间，例如向财务索取附表，
  未明确优先询问目的地；本次不把这种建议质量计为已完全解决。
- 逐条审核仍由模型判断语义。程序能保证协议完整与流程有界，
  不能数学保证任何模型都不会漏掉条款限定。
- 未执行浏览器、槽位提取及保存会话的完整端到端验收，未重启网页服务。
  正在运行的服务需要重启才能加载这些修改，旧历史回答不会自动改写。
