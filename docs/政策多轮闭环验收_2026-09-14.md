# 政策多轮闭环验收

日期：2026-09-14，Asia/Shanghai。

## 范围

验收“追问、分步补充、完成原任务、更正条件、重新生成结论”的政策问答闭环。
沿用现有 LangGraph、PostgreSQL 和已发布的 V1.1 模拟制度，不引入新框架、表或模型。
本轮未改密钥、正式账号、制度、业务金额、生效日期或向量数据。

## 已确认的问题

首轮真实浏览器12轮问答、14项检查，11项通过、3项失败。

用户先询问住宿上限，再补充武汉、单人入住、普通员工，系统正确回答340元。
接着用户说“目的地改成杭州，其他条件不变，住宿上限重新看一下”，
抽取器却将 `policy_explain` 改成 `policy_check`，独立复核器也接受了这次变更。
结果是原解释任务变为 `blocked`，新增核验任务追问费用日期，没有继续回答上限。
随后的历史日期切换也沿用了错误的核验任务，恢复日期时虽重新回答，但任务链断言仍失败。

另外，首个追问请求明确指定2026-09-14，但该次抽取没有将其放入 `expense_date`，
只保留在问题文字中；解释入口恰好默认到同一天，因此单看回答无法暴露遗漏。

代码核对确认：原 `pending_tasks` 排除了已完成任务，抽取/复核缺少稳定的已完成目标上下文；
原协议也没有要求意图变化单独提交当前原话证据。不是金额规则或分块丢失。

## 修改

1. 抽取及复核同时接收任务上下文 `task_context`，包括已完成任务；未完成控制仍使用 `pending_tasks`。
2. 更新同一事项若改变当前版本已有任务的意图，必须提交 `intent_change_evidence`。
   程序校验当前消息索引和原话存在，复核器判断是否真的授权另一种操作；缺失或复核失败则整批不提交。
3. 明确“解释适用标准”不因补充城市、职级而自动变成“核验实际费用”；
   后续 `question` 应承接原目标与更新条件，不只传孤立的补充句。
4. `expense_date` 在制度解释中承载明确指定的政策适用日期，要求抽取与复核检查遗漏。
   不写具体日期识别正则，不将城市、职级、金额或问句写入生产分支。
5. 浏览器证据增加完整任务快照及下游实际收到的问题、日期和事实。
   这些观测只存在于隔离测试入口，不给正式接口增加原始模型日志。

现有事项合并、revision、结果失效和任务 ID 复用机制未重写；无需迁移检查点。

## 验收方法

### 确定性回归

- 使用脚本模型、内存检查点和合成制度，实际执行 LangGraph、槽位校验、任务调度、检索及回答验证。
- 连续六轮覆盖缺条件、分步补充、城市更正、历史无政策、日期恢复。
- 断言任务 ID 保持、revision/attempt 递增、旧结果替换、下游日期和合并事实正确。
- 断言已完成目标同时进入抽取器与复核器，而不是仅存在于可被截断的聊天历史。
- 意图门禁覆盖缺证据拒绝、真实当前引用仍需复核、复核拒绝及过期引用拒绝。
- Python全量493项通过、0跳过，包含显式开启的隔离PostgreSQL集成测试，47.152秒。
- 后续加强上下文断言后，35项政策定向测试通过；Node SSE5项通过；依赖一致性检查通过。

脚本模型测试证明状态与协议行为，不证明模型自然语言理解能力。

### 真实浏览器

通过 Edge + Playwright 在随机端口启动工作区服务，创建随机密码的临时账号及独立记忆schema，
读取原有已发布政策，调用真实配置模型与Embedding。没有替换模型回答或检索结果。

每轮从输入框发送，检查SSE请求成功、无页面报错、输入框恢复；
再读取会话历史核对任务 ID、意图、状态、revision、attempt 和结果引用。
对关键轮次额外检查实际下游日期、目的地及职级。引用、金额、追问与历史版本缺失均有内容断言。

修复后首轮14轮问答、16项检查全部通过；最终加入跨城市、职级及非当天日期交叉验证，
共17轮问答、19项检查通过，0项失败，浏览器错误列表为空。

## 限制

- 语义识别与日期遗漏检查仍依赖模型及独立复核；原话存在不等于语义正确，不能保证任意输入都正确。
- 未做大规模措辞稳定性、压力、对抗注入或多事项歧义评测；有限通过不等于全项目验收。
- 本轮不包含酒店、交通、地图供应商联调，也没有实现独立reranker。
- 回答仍偏长，附加条款较多；本轮没有对简洁性设置验收指标。
- 历史2026-09-01没有已发布适用政策属于资料边界，正确行为是明确缺失，不是补造版本。
