# 查询契约改造验收

日期：2026-09-13

## 1. 结论与范围

本批完成 P0 的离线基线与最小规划追踪、P1 查询契约实施。

## 2. 实施内容

| 模块 | 改造 |
| --- | --- |
| `contracts.py` | 共享字段及酒店、交通、组合契约；往返日期校验；旧请求兼容；执行字段投影 |
| `slots.py`、`semantic_review.py` | 查询范围与方向经过原话证据和语义复核；新任务不得缺范围回退到交通 |
| `graph.py` | 按范围构建请求；缺信息追问；过去入住日期拦截；只展示本次采用字段 |
| `planning.py` | 按组件查询与检查完整性；过滤失败响应和不匹配候选；记录耗时与选择次数 |
| `providers.py`、`tuniu.py` | 适配新契约；显式范围拒绝无关调用；保留旧请求错误码 |
| `plan_checks.py`、`policy_guard.py` | 按范围展示；区分空结果与服务失败；新增字段中文名称 |

原事项保留不相关的历史事实，但执行请求不携带这些字段。
这是通用组件协议，不通过城市、日期或用户样例硬编码意图和答案。
枚举范围属于程序接口约束，不保证模型必然正确理解任意表达。

## 3. 如何验收

使用项目已有 `.venv` 和 unittest，不安装额外依赖。
新增 `tests/test_query_contracts.py` 的 24 个测试方法，其中组件矩阵覆盖
三种交通模式、两种含交通范围、两种方向的 12 个组合。
脚本模型只提交预设工具参数，供应商使用明确的模拟数据，运行真实图和校验代码。
因此以下“结果”是离线断言结果，不是实际模型生成回答的逐字记录。

| 问题或操作 | 验证的结果 | 状态 |
| --- | --- | --- |
| “查 B 酒店”，只给目的地 | 提示入住、退房日期，不要求出发地和出发日期；供应商调用数为零 | 通过 |
| 随后补充入住、退房日期 | 沿用同一事项，版本递增，只调用酒店查询 | 通过 |
| 要查往返机票，却没有返程日期 | 提示返程日期，不额外要求酒店日期；不调用供应商 | 通过 |
| 单程、往返、交通与酒店组合 | 严格按范围、方向、交通模式构建查询阶段 | 通过 |
| 组合查询改为“只查酒店” | 新建对应草案；保留旧出发地事实，但不执行交通、不展示为本次采用事实 | 通过 |
| 交通查询扩大为组合，未给酒店日期 | 清空旧草案及旧结果并追问，不把旧交通草案当完整新结果 | 通过 |
| 酒店入住日期已过去 | 在供应商调用前拒绝并提示日期问题 | 通过 |
| 酒店查询未给员工职级 | 酒店仍可查询；政策核验保持信息不足，不视为批准 | 通过 |
| 查询成功但没有候选 | 展示查询成功但无候选，保留不完整状态 | 通过 |
| 查询报错或服务不可用 | 展示失败或不可用，不称为成功无结果 | 通过 |
| 失败响应夹带候选，或返回了错误组件 | 候选不进入选择及备选结果 | 通过 |
| 候选选择阶段超时 | 保留尝试次数、阶段耗时与错误状态，不展示异常原文 | 通过 |
| 新事项不填范围，或将显式范围清为 null | 提交层拒绝，不落回旧交通行为 | 通过 |
| 查询范围只引用旧轮次原话 | 原话证据校验拒绝，不绕过当前输入证据要求 | 通过 |
| 无范围的旧事项补充出发日期 | 保留事项 ID、递增版本，仍用旧交通契约，不静默变成酒店 | 通过 |
| 两家适配器处理酒店独立请求 | 无交通字段也可规范化；拒绝无关组件调用 | 通过 |

开发中实际出现的失败及处理：

- 新契约尚未实现时新增测试导入失败，随后实现生产契约。
- 新范围检查曾改变途牛旧请求的日期错误码；调整检查边界及顺序，保留旧断言。
- 新酒店模拟响应误用了航班成功标志；按已有酒店协议修正夹具，未放宽生产解析。
- 两项新测试暴露缺范围与清空范围可走旧回退；增加提交门禁，先失败后通过。
- 既有图测试的脚本响应按新提交协议补充预设范围，原业务断言保留。
  脚本夹具不是生产意图分类器，不能用这部分通过率证明模型识别能力。

最终执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_query_contracts -q
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -q
.\.venv\Scripts\python.exe -m pip check
git diff --check
```

定向测试 24 项全通过；全量结果如上；依赖检查无破损依赖。
Git 差异检查通过，仅有既有换行符警告。
仓库含大量未跟踪文件，不能仅用 Git 差异检查声称这些文件全部被检查。
