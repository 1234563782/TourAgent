# 并发与配额改造验收

日期：2026-10-27。范围为既有并发准入机制的加固，不改供应商、RAG、记忆语义或消息契约。

## 结论

- 等待队列从"名义排队"改为真排队：默认等待 10 秒，轮询带随机退避，准入与排队阶段不再改写历史运行记录。
- 单次请求的模型调用额度改为分段预留，`REQUEST_CALLS` 从"每次预留数"变成"硬上限"，`24 < MAX_STEPS(30)` 的矛盾从结构上消失。
- 新增单次请求墙钟上限，慢供应商不能再长期占用全局执行槽位。
- 补三条启动期不变量，并把 advisory lock 键改为带 schema 前缀。
- 数据表结构未变，**不需要**重新执行 `init-resources`，只需重启服务。

## 变更点

| 文件 | 变更 | 行为 |
| --- | --- | --- |
| `business_travel/resources.py` | `RequestBudget` 增加 `tranche/extend/deadline`，`_charge`/`_reserve_request`/`_extender` 拆分 | 准入预留一段，用尽后在同一事务内原子续借；续借被日额拒绝属于执行中失败 |
| 同上 | `_settle` 独立，退款额按"已预留 − 已使用"，异常不外抛 | 崩溃/断连保守保留预留，且不替换导致运行结束的原始错误 |
| 同上 | 队列轮询加随机退避；`Slots.release/close` 容错 | 等待者不再同刻撞锁；死连接不再抛错 |
| 同上 | `_key` 加入 `memory_schema` 前缀 | 同库不同 schema 不共享槽位 |
| `business_travel/settings.py` | 新增 `resource_call_tranche`(8)、`resource_request_deadline`(180)；`request_calls` 24→40；`queue_timeout` 2→10；`poll_seconds` 0.05→0.1 | 真排队 + 分段预留 + 墙钟 |
| 同上 | `validate_resources` 增加三条不变量 | `request_calls ≥ max_steps + 8`；`global + queue ≤ 16`；保留原有池容量校验 |
| `business_travel/web.py` | `interrupt_orphans()` 移到准入之后 | 429 拒绝的请求零副作用 |
| 同上 | `RunDeadlineExceeded` → 503（与调用上限同一"核实/恢复"路径） | 执行中终止，不新建前端分支 |
| 同上 | `conversation_lock` 键加入 schema | 与槽位键保持一致 |

## 不变量与失败边界

| 场景 | 行为 |
| --- | --- |
| 单次请求超过调用硬上限 | 停止后续模型调用，503 + failed 运行，走核实/恢复 |
| 单次请求超过墙钟 | 同上，且立即释放槽位 |
| 续借时用户/公司日额不足 | 执行中失败（503），**不是** 429，因为运行已经开始 |
| 正常退出 | 退还"已预留 − 已使用"，两处 scope 同日同事务 |
| 进程崩溃/连接中断 | 不退款、不重试、不抛错；槽位由会话销毁自动释放 |
| 队列满载 | 立即 `queue_full` 429 |
| 队列等待超时 | `queue_timeout` 429，`Retry-After` = 队列超时 |
| 配置不自洽 | 启动即 `ValueError`，不带着错误阈值上线 |

## 验证

```powershell
$env:TRAVEL_TEST_POSTGRES='1'
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_resources tests.test_resources_live -q
```

结果：30 项全部通过（离线 10、隔离 PostgreSQL 20），其中新增 5 项：

- `test_call_budget_extends_in_tranches_and_stops_at_ceiling`
- `test_refused_tranche_extension_never_reaches_provider`
- `test_request_deadline_blocks_provider_call`
- `test_call_tranche_reserves_then_extends_and_refunds_remainder`（live）
- `test_refused_tranche_extension_is_execution_failure_not_admission`（live）
- `test_request_deadline_blocks_next_call_and_releases_slot`（live）

改造过程中由新用例发现并修复一处真实缺陷：准入按 `CALL_TRANCHE` 实扣、
预算却按 `min(TRANCHE, REQUEST_CALLS)` 记账，导致退款多退；现由
"实扣金额 = 预算预留金额"约束保证一致。

同时运行了 80 个测试模块：33 个模块通过（含 `test_web_chat`、`test_auth`、
`test_conversations`、`test_chat_runs`、`test_attachments` 及全部可选 PostgreSQL 模块）；
其余模块的失败均发生在 `tempfile.TemporaryDirectory` 的清理阶段
（`PermissionError [WinError 5]`），属当前执行环境的沙箱限制，与本次改动无关，
需在可写临时目录的环境复跑完整 649 项。

## 未验证或未实现

- 未做高并发长稳压测，不承诺吞吐与排队时延分布。
- 队列仍不承诺严格 FIFO（未引入票据序列表）；如指标显示 `queue_timeout` 占比过高再单独治理。
- 未新增准入/排队指标（`admission_rejected`、`queue_wait_seconds`、`slot_in_use`），下一批处理。
- 多进程阈值一致性仍依赖部署纪律，未加启动期配置指纹校验。
