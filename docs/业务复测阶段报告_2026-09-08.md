# 业务修复与复测阶段报告

日期：2026-09-08，Asia/Shanghai。本报告不是全部验收通过或上线批准。

## 本轮修改

- 偏好工具使用明确的 type/value 模型结构，保持确认中断和拒绝不写入。
- 政策子 Agent 接收当前线程的原始用户消息，返回结构化 rule_checks。
- 工具异常保留异常类别，不输出可能含密钥的异常正文。
- 主助手提示补充金额变化重新核验、保留来源要求。这些提示不是代码强制保障。
- 新增四项回归测试，覆盖 schema、确认/拒绝/错误字段、上下文传递和异常脱敏。

## 怎么验收

1. 先增加三个回归测试，观察修复前失败；修改后通过，再增加拒绝与非法字段回归。
2. 使用项目 .venv 和现有 unittest，不安装依赖、不改 .env。
3. 使用原 tests/acceptance_cases.json 和 tests/acceptance_rules_cases.json，未改问题和预期。
4. 通过 build_assistant 调用真实模型、政策检索、途牛和信息工具。
5. 各组独立测试身份、SQLite 记忆和内存检查点；同组多轮共享上下文。
6. 仅在真正出现 interrupt 时模拟接受或拒绝，不把自然语言确认当成中断。
7. 人工核对最终回答、实际工具结果、事实保真、来源、确认和保存结果。
8. completed 仅代表图正常返回，不代表业务通过。查询结果和模型回答存在波动。

首个沙箱运行出现 OpenAIConnectionError，授权联网后新建目录复测，未覆盖失败记录。
没有预订、支付、审批、政策发布或正式用户记忆写入。
