# 上下文预算与压缩

## 已实现的策略

预算默认启用，不需要新密钥、数据库表或第三方依赖。只压缩每次发给模型的输入视图，
PostgreSQL 检查点中的原始消息、消息顺序、用户原话序号与业务状态保持不变。

1. 固定保留系统约束、当前问题、已校验的相关业务状态、待确认信息和待恢复的失败原话。
2. 近期历史按完整对话轮次选择，不单独留下工具响应，也不截断当前轮次的工具调用链。
3. 更早历史改成带原始消息序号、覆盖范围和 SHA256 的导航摘要。
   摘录只能保留完整用户原话，放不下就省略，不能切掉否定或条件。
4. 已结束轮次的大工具结果改为原文引用；当前轮次结果不截断后继续推断。
   对成功的 `read_task_result`，主助手接收完整确定性展示文本及原始消息引用，
   不重复传入展示文本已经覆盖的嵌套结构；未知的原始字段不得推断，需按引用回查。
   原始工具结果仍完整持久化，工具调用链不变，允许继续读取其他任务结果。
5. 主助手可调用 `read_conversation_history` 按原始消息序号回查当前会话，长消息分页读取。
   业务结果仍优先使用带任务版本校验的 `read_task_result`。
6. 每次模型调用前检查总预算，计算消息、工具描述、参数 schema 和修复重试追加内容。
   保护范围覆盖主助手、槽位提取、语义复核、规划选择、政策回答及政策回答复核。

摘要只是导航，不是事实、政策证据或新的执行授权。当前已校验状态和最新原话优先，
读取旧金额不会恢复已撤回金额，读取旧的“同意保存”也不会自动获得新授权。

## 哪些内容不能随意压缩

- 当前用户原话及当前轮工具调用/响应配对；成功业务结果回读采用上述完整展示视图。
- 已校验事项、任务版本、待确认操作。
- 失败请求恢复所需的完整原话与原序号。
- 政策检索的必要证据及例外条款。

这些必要内容放不下时，返回明确的预算不足提示，不静默删减后生成看似完整的结论。
规划选择超限仍保留已经查询到的候选；主助手在工具后超限仍展示已有结果及超限原因。
已完成的普通闲聊任务仅从模型任务快照中省略，持久化账本不删除；业务任务继续保留。

## 配置

未配置时使用下列默认值。需要调整时在项目 `.env` 添加对应变量，不必改代码；
环境变量优先于 `.env`。应用需重启后读取新值，本次未修改用户真实 `.env`。

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `TRAVEL_CONTEXT_WINDOW_TOKENS` | 65536 | 部署使用的上下文上限，须按实际模型核实 |
| `TRAVEL_CONTEXT_OUTPUT_TOKENS` | 8192 | 输出预留，同时传给模型的 `max_tokens` |
| `TRAVEL_CONTEXT_MARGIN_TOKENS` | 4096 | 供应商模板等开销的安全余量 |
| `TRAVEL_CONTEXT_FRAME_TOKENS` | 1024 | 历史导航、序号等输入组装预留，不改变最终输入上限 |
| `TRAVEL_CONTEXT_RECENT_TOKENS` | 12000 | 近期历史目标预算；不据此截断当前轮 |
| `TRAVEL_CONTEXT_SUMMARY_TOKENS` | 2048 | 历史导航摘要上限 |
| `TRAVEL_CONTEXT_TOOL_TOKENS` | 2048 | 老轮次工具正文改为引用的阈值 |
| `TRAVEL_CONTEXT_READ_TOKENS` | 6000 | 历史回查每页正文预算，不含响应元数据 |
| `TRAVEL_CONTEXT_ROLE_INPUT_TOKENS` | `{}` | 按角色进一步缩小输入预算的 JSON 对象 |

角色支持 `supervisor`、`slots`、`reviewer`、`planner`、`policy`、`policy_reviewer`。
例如 `{"planner":24000}` 限制规划选择输入，不提高全局上限。
槽位窗口仍受 `TRAVEL_SLOT_CONTEXT_LIMIT` 控制，但以完整轮次为单位，当前轮不按条数截断。

默认全局输入预算为 `65536 - 8192 - 4096 = 53248`。
数值不是自动识别的模型规格。所有角色共用当前配置的模型，若模型规格不同应重新核实预算。
过小的角色预算可能连提示词和 schema 都放不下，此时调用会被直接阻断。
组装预留须为非负整数且小于全局输入预算；允许设为0，最终门禁仍生效。
角色预算小于组装预留或必要内容时会明确阻断，不会静默截断。

### 计数的准确性

当前采用 JSON 的 UTF-8 字节长度加消息封装预留作为保守估算，不下载 tokenizer。
配置和观测字段沿用 `tokens` 命名，但输入估算值不是供应商实际账单 token；
不能据此计算费用，也不能宣称数学上保证任意供应商都不会超限。
输出 `max_tokens` 仍按供应商 API 的 token 语义发送。

不同供应商的隐藏模板、工具编码方式可能不同，因此额外保留安全余量。
需要精细利用窗口时，可后续接入已核实的模型专用计数器，并与供应商 usage 做校准。

### 逐次调用校准

每次 `invoke` 创建独立的 `context_budget` 父观测，底层 `chat_model` 是其子节点。
筛选 `budget_stage=invoke` 查看调用，`assembly` 仅为历史组装检查，不计作模型调用。
修复重试每次拥有新的 `call_ref`；供应商内部隐藏尝试不在本地单独计数，当前工厂关闭SDK重试。

- `context_role`：模型角色；`model_ref`：配置模型名的HMAC引用，同一观测密钥下可分组，
  不上传原模型名、URL、密钥、提示词或响应正文，不从供应商返回的任意metadata猜模型。
- `estimated_input_tokens`：消息及工具schema的字节估算；`estimate_method=utf8_json_v1`。
- `input_tokens`：响应标准化 `usage_metadata.input_tokens`，与子模型观测对照。
- `input_estimate_delta`：估算减实际，负值表示本次低估。
- `input_estimate_ratio`：估算除实际，大于1表示本次高估；实际为0时不生成比值。
- `usage_status`：available为有效用量，missing为未提供，invalid为格式无效，
  not_called为尚未调用（包括预算阻断），unavailable为调用失败未取得响应。缺失不补0。
- `budget_decision`：allowed或blocked；预算阻断时无实际用量。异常status不替代预算判断。

观测不可用时不改变业务结果、不额外重试；不自动降低余量或调整窗口。
应按模型引用、角色、估算方法分组，关注差值分布、低估样本和用量缺失率，
不能把少量短句或平均偏差当成长会话的安全上界，也不能把估算值当账单用量。

## 数据及权限边界

- 摘要存于现有会话检查点的 `context_summary`，不是用户长期记忆或偏好。
- 当前摘要每次从原始历史重建，是确定性摘录，不调用模型重写，不做增量摘要缓存。
- 原文工具没有任意用户或会话参数，仅读取框架注入的当前会话状态。
- 分页可能切开条款，响应明确标为不完整，不允许据局部页作政策结论。
- Langfuse 仅接收角色、估算量、预算和结果状态等白名单元数据，不新增正文上传。

## 当前限制

这不是无限上下文。业务事项、当前工具结果、政策证据仍可能增长到超过预算；
当前策略会保守失败，而不是任意丢弃。很早的普通聊天细节不保证自动召回，
若摘要不能消除指代歧义，应回查或追问。

完整历史仍占数据库空间；本次不实现归档删除、增量摘要缓存、跨会话语义记忆检索，
也不解决进程崩溃后的工具执行恢复。摘要来源校验和程序门禁不能保证模型永远正确理解自然语言。
